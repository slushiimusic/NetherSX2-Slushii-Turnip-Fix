# v26500800 — Gameplay and Daijisho preview

This preview simplifies Graphics settings, removes avoidable startup work, and adds an optional Daijisho connector. It is based on the same Classic 3668 core as v26500723. It does not claim to fix every game's compatibility or guarantee 60 FPS.

## What changed

- Common controls appear first: renderer, internal resolution, aspect ratio, widescreen, 60 FPS patches, frame generation (FRAMEGEN only), and Show FPS. Expand **Advanced graphics** for the other controls. No existing controls were removed.
- Shader preparation runs on a worker. Reading framegen readiness no longer waits for that worker, and a late completion cannot undo a user's OFF choice or attach to an old game screen.
- Repeated settings refreshes are combined. The hidden FPS overlay no longer repeatedly raises itself over the pause menu. The framegen monitor stops after exiting a game, and unchanged FPS text no longer triggers another text update.
- OpenGL and Software selections survive startup. New installs default to native resolution and accurate readbacks; existing choices are preserved. The performance preset no longer changes readback mode.
- The framegen FPS line uses aqua text and distinguishes **Source FPS** from **Display FPS**. Generated frames improve displayed motion, not emulation speed.
- Flow remains **0.25**, artifact protection remains **OFF**, and 60 Hz framegen support is retained. Prior icon and Control Settings tab fixes are included.

## Install

Choose **FRAMEGEN** or **NONFRAMEGEN** and install it over the existing Pink app. Both use package `xyz.aethersx2.cpink02` and the existing signing certificate. Do not uninstall Pink or clear its data. Switching variants uses the same save states, memory cards and settings.

FRAMEGEN needs your own Lossless.dll. NONFRAMEGEN removes the framegen controls, capture runtime and LSFG library. Both use the unchanged NetherSX2 Classic core based on AetherSX2 3668; v26500800 is the Slushii package version.

## Daijisho

1. Install the optional **Slushii-Daijisho-Connector-v1.apk** alongside Pink.
2. Add your game folder in Pink so it has access to the files.
3. In Daijisho's PS2 platform editor, select **ps2 - NetherSX2 Turnip** as the player, then open a game.

The connector matches that existing entry's package and launch component, then forwards the game to Pink. It adds a clearly named **Daijisho Connector** helper icon because Daijisho checks launcher entries before starting a player. It contains no emulator or saves. The **Classic** entry opens the separate Classic app.

If a real emulator already uses package `xyz.aethersx2.tturnip`, keep it installed and use the custom player instructions in [the connector guide](https://github.com/slushiimusic/NetherSX2-Slushii-Turnip-Fix/blob/main/compat/daijisho/README.md) instead. This is an unofficial connector.

## Validation and limits

Host regression checks cover native-resolution seeding, saved resolution and renderer preservation, nonblocking shader readiness, delayed OFF handling, OSD settings, resolution rebuilds, widescreen recovery, save protection, 60/120 Hz support, frame pacing and Control Settings layout. Both signed variants pass version, package, signature, alignment, icon/name, preference-layout and variant-content checks.

Nova checks passed for launch from Daijisho 1.5.0, resolution changes in 4:3 and widescreen, FPS visibility, and game exit. All eight original save-state and memory-card files, plus the seven backed-up configuration files, remained byte-identical after installation and testing. Test settings were restored.

The emulator core and FRAMEGEN LSFG library are byte-identical to v26500723. The APKs do not include BIOS files, games, Lossless.dll or user saves.

Device checks and their limits are recorded in the [validation receipt](https://github.com/slushiimusic/NetherSX2-Slushii-Turnip-Fix/blob/main/releases/v26500800-validation.json). No clean before/after FPS benchmark was possible while Nova was also receiving a large background file transfer. Thor and the reported Android 14 / Snapdragon 8 Gen 1 crash have not been tested with this build. The Xenosaga Episode I stale-loading-image report remains unresolved.
